## 一、录屏前 10 分钟准备

### 1. 环境

1. 启动后端与前端（`start-server.bat` + `start-web.bat`），确认 `http://localhost:8082/api/health` 返回 200。
2. 浏览器开无痕窗口，访问 `http://localhost:5173`，F11 全屏。
3. 分辨率 1920×1080，浏览器缩放 110%；关闭书签栏、扩展弹窗、系统通知。
4. 提前登录好 `#/admin`，**不要在镜头里输密码**；令牌 12 小时有效，录前重新登录一次。
5. 先完整跑一遍三个示例，再开始录，避免第一次冷启动卡顿。

### 2. 数据

1. 清掉测试成分、测试分享、测试反馈；不要在镜头里出现「时间测试甲」这类名字。
2. 研究任务页只保留 **已完成** 的真实任务；失败任务在录前重试或删除，不要录「失败 / 重试中」。
3. 至少准备一条 **AI 深度描述已写入** 的成分（如水、甘油），录前台成分卡和报告详情时使用。
4. 如果要录「括号变体自动合并」，提前用真实模型跑一次 `(日用)香精`，确认任务已完成、别名已合并；**不要在镜头前现场等模型**。注意：合并只补别名，不会给「香精」自动写 AI 描述；AI 描述镜头用另一条已研究成功的成分。
5. 主片用的示例报告最好 **0 待补全**：先把示例里的未知成分研究/补齐，或换一个全部命中的示例。
6. 历史报告留 1–2 份即可，方便录「历史」；不要把隐私产品名留在列表里。

### 3. AI / 拍照（可选镜头）

- 研究 API：先在「API 与模型 → 测试研究」用「烟酰胺」确认能稳定返回 JSON。**不稳就跳过现场研究，改录已完成的任务和已有的 AI 描述**，不要录失败。
- 视觉 API：如果要录「拍照自动填产品名」，先用真实包装试一次，确认 `productName` 能返回；失败就改用粘贴示例，不要录报错。
- 镜头里不要点「显示 Key」，不要录完整 API Key、分享短链里的隐私内容。

### 4. 推荐标签页顺序

1. 前台首页（输入页）
2. 报告页
3. 成分库 `#/ingredients`
4. 管理控制台 `#/admin`（已登录）
5. 研究任务页
6. API 与模型页

## 二、主片：5 分钟

### 0:00–0:20 ｜冷开场：唯一不撒谎的部分

**画面**
- 真实护肤品背面特写，成分表小字占满画面。
- 叠字：**「广告会夸张，成分表不会。」**

**旁白**
> 这是一瓶护肤品背面的成分表。大多数人从来没读完过它。
>
> 但它其实是这瓶东西里最不会撒谎的部分——法规要求，成分必须按含量从高到低排列。

### 0:20–0:45 ｜产品出场

**操作**
- 切到 `http://localhost:5173`。
- 点「示例 · 美白精华液」，产品名自动带入。
- 右侧档案保持「油性 · 敏感肌」。
- 点「开始解读」。

**旁白**
> 我们做了一个工具，叫成分镜。
>
> 它不查「这个成分好不好」，而是把这串顺序，翻译成「这瓶东西对你意味着什么」。

**字幕**
- 位置即含量
- 同一瓶，对不同的人结论不同

### 0:45–1:35 ｜报告：把顺序翻译成结论

**操作**
- 报告出现，停在结论卡：等级、标题、档案。
- 往下滚到「配方梯队」，鼠标沿着前 5 位、6–10 位、11 位之后三档移动。
- 指到「烟酰胺」在第 12 位。
- **点烟酰胺的胶囊**，弹出成分详情卡：角色、分类、深度描述、风险、第 12 位、别名。
- 关闭详情卡。

**旁白**
> 这是一瓶主打烟酰胺美白的精华。
>
> 但你看，烟酰胺排在第 12 位。前面还有 11 个成分，含量都不低于它——它不是这瓶的主要功效成分。
>
> 名字印在正面，含量排到后面——这就是概念添加。
>
> 点开任何一个成分，能看到它在这次配方里的位置、作用、风险和别名。不是一张孤立的成分百科，而是「在这瓶里」的成分。

**字幕**
- 第 12 位 ≠ 主功效
- 点成分 → 看详情

### 1:35–2:15 ｜个体化：同一瓶，不同结论

**操作**
- 报告顶部点「调整档案」。
- 关闭「敏感肌」，报告就地重算，指结论卡下方的变化提示（风险 6 → 2）。
- 再打开「敏感肌」，恢复。
- 切到「抗老紧致面霜」示例，打开「孕期/备孕」。
- 指风险区的「孕期建议避开：视黄醇」。

**旁白**
> 同一瓶东西，对不同的人，结论可以完全相反。
>
> 关掉敏感肌，需要留意或避开的成分从 6 个降到 2 个；变化直接写在报告里，不用你自己对比两份。
>
> 换成抗老面霜，勾上孕期，视黄醇会直接进「建议避开」。这一条不是模型猜的，是写在规则里的硬约束。
>
> 哪些能交给模型，哪些不能——这条线必须清楚。

**字幕**
- 规则判定，不靠模型猜
- 风险按类型合并，不制造噪音

### 2:15–3:05 ｜AI 研究：补全，但不替你做决定

> **两条录法，按 API 稳定性二选一：**
> - **A 稳定**：现场扫 `水、(日用)香精`，看报告进入研究队列，再等自动刷新。
> - **B 稳妥（推荐）**：录已经完成的研究任务和已写入的 AI 描述，不现场等模型。
>
> 无论哪条，都不要录失败、反复重试和空白等待。

**操作（B 稳妥版）**
- 切到 `#/admin` →「研究任务」。
- 筛选「已完成」，指一条任务：原始名称 `(日用)香精`，结果 `香精`，证据「已合并为已有成分的别名」。
- 切到 `#/ingredients`，搜「水」或「甘油」，指 AI 深度描述和「AI 深度研究」标记。
- 回报告，点「水」的详情卡，指 AI 描述和「AI 深度研究」。

**旁白**
> 成分库不可能一开始就收全。扫描到没收录的成分，会先进研究队列，由后台自动研究。
>
> 比如 `(日用)香精`，模型归一成「香精」。它不是新建一条重复数据，而是自动并成「香精」的别名；下次扫描就能直接匹配。
>
> 研究成功的成分会补上一段更完整的描述，前台卡片和报告详情都会展示。
>
> AI 结果不会直接变成正式数据：先回「待研究」，报告标注 AI 补全，人工确认后才转为已确认。失败也不会无声消失，任务、错误和重试都在后台。

**字幕**
- 未收录 → 研究队列
- 成功写库；失败可重试
- 括号变体自动并别名
- AI 结果待人工确认

### 3:05–3:45 ｜成分库：不是表格，是能读的卡片

**操作**
- 打开 `#/ingredients`。
- 搜「烟酰胺」；指卡片上的作用、风险标签、别名。
- 搜「水」；指 AI 深度描述和「AI 深度研究」标记。
- 搜「香精」；指别名里已有 `(日用)香精`，说明同义词变体能直接匹配。
- 清空搜索，展示卡片网格。

**旁白**
> 成分库不是一张只给专业人看的表。
>
> 每个成分是一张卡片：一句话作用、风险、孕期和敏感肌提示、别名；研究过的成分，会多一段更完整的描述。
>
> 它解决的是「我看不懂标签」，不是「再给我一个成分查询框」。

### 3:45–4:35 ｜管理控制台：一套能运营的后台

**操作**
- 切到 `#/admin` 概览：成分库、待研究、已确认、分享、研究队列检查项。
- 进「成分数据」：指三个状态页签、描述列、添加时间列。
- 把排序切到「最新添加」，再切回；指新增按钮。
- 进「研究任务」：指状态、尝试次数、错误/结果、重试。
- 进「API 与模型」：三块卡片，**不点显示 Key**；指「留空回退总 API」。
- 进「系统状态」：指数据文件、研究服务、视觉服务。
- 回「分享报告」：打开一份报告，指短链和删除。

**旁白**
> 这不是一个只在前台好看的 Demo。
>
> 后台可以维护成分状态、写深度描述、看添加时间；可以配置总 API、视觉 API、研究 API；可以看研究队列、失败原因、重试；也能管理分享和反馈。
>
> 模型不是写死的：总 API 兜底，视觉和研究可以各用各的模型；研究失败会留下任务，不会把「没研究出来」伪装成成功。

**字幕**
- 数据 / 模型 / 队列 / 分享 / 反馈
- 单机部署，数据在本机

### 4:35–4:55 ｜可信度：为什么不用向量匹配

**画面**
- 切到架构图/代码 10–15 秒，或叠字。
- 可预先录一段 `mvn test` 通过画面，不要现场敲命令。

**旁白**
> 成分匹配我们不做向量检索。羟苯甲酯和羟苯丙酯在向量空间几乎重合，混淆就是安全事故。
>
> 匹配走标准名、别名、包含匹配；判定交给规则；模型只负责把模糊图片变成文本、把新成分补成结构化数据。

**字幕**
- 标准名 → 别名 → 包含匹配
- 规则判定；AI 补全
- 30 秒研究超时；失败可重试

### 4:55–5:15 ｜收尾

**操作**
- 回报告顶部，停在结论卡；如果手边有真实产品，最后一镜拿起来。

**旁白**
> 我们不评价这瓶东西好不好，也不推荐你买哪瓶。
>
> 我们只做一件事：把成分表翻译成人话，让你在货架前就能看懂。
>
> 成分镜——看懂这瓶，适不适合你。

**字幕**
- 成分镜 · 看懂这瓶适不适合你
- 只读标签信息，不构成医疗建议

## 三、3 分钟投稿版怎么剪

从 5 分钟主片里保留：

1. 0:00–0:20 冷开场
2. 0:20–0:45 产品出场
3. 0:45–1:35 报告 + 成分详情卡
4. 1:35–2:15 个体化（只保留敏感肌切换，删孕期）
5. 2:15–2:50 AI 已完成任务 + 香精别名 + 前台 AI 描述（用「水」/「甘油」，删后台 API/系统）
6. 2:50–3:00 收尾

删掉：

- 3:05–3:45 成分库完整走查（只留 3 秒卡片特写）
- 3:45–4:35 管理控制台完整走查（只留 3 秒概览）
- 4:35–4:55 技术架构
- 所有等待模型、切换标签页、鼠标找按钮的空镜

3 分钟版仍然要保留一句：**「AI 结果先待研究，人工确认后才转已确认。」**

## 四、8 分钟完整版怎么加

在 5 分钟主片基础上补：

1. **拍照自动填产品名**（30 秒）：上传清晰包装图 → 产品名自动填入 → 成分表识别。失败就不录。
2. **研究队列失败与重试**（40 秒）：任务失败 → 错误可见 → 重试 → 完成。只在 API 稳定、能一次成功时录。
3. **括号变体合并**（30 秒）：`(日用)香精` → 任务完成 → 别名 → 再分析 0 待补全。
4. **API 三块配置**（40 秒）：总 API / 视觉 / 研究，留空回退；不显示 Key。
5. **成分时间与排序**（30 秒）：添加时间列、最新/最早/名称排序、新增后置顶。
6. **分享与历史**（30 秒）：复制短链、新窗口打开、历史回放。
7. **工程与限制**（60 秒）：`mvn test`、无数据库/单机存储、30 天分享清理、AI 可能出错、人工复核。

## 五、常见翻车点

| 情况 | 处理 |
|---|---|
| 页面提示连不上后端 | 确认 8082 健康接口；后端改过代码要先重启 |
| 后台还是旧数据/旧字段 | 后端重启；刷新页面；确认工作目录一致（`server/data` 与项目根 `data` 不要混） |
| 研究任务全是失败 | 录前重试/删除失败任务；只录已完成；不要现场等模型 |
| AI 描述为空 | 换一条已研究成功的成分；不要现场等研究 |
| 拍照产品名没填上 | 模型可能没按 JSON 返回；改用粘贴示例，不要录失败 |
| 管理台登录失效 | 录前重新登录，避免录到登录页 |
| 画面出现完整 Key / 密码 | 不要点「显示」；录前检查标签页和剪贴板 |
| 表格太宽 | 1920×1080 + 110% 缩放；必要时只录前 6 列 |
| 字幕来不及 | 剪映智能字幕后校对专有名词：成分镜、烟酰胺、视黄醇、羟苯甲酯 |
| 等待 AI 太久 | 剪掉等待；用已完成任务替代现场调用 |
