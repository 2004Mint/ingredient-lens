# 成分镜 · 演示视频脚本 v2（省赛提交版 · 7 分钟）

> 适用：全国高校 AI Web 开发挑战赛 · 省赛作品提交（截止 2026-11-18）
> 对标硬性要求：**5–8 分钟 / MP4 / ≥1080p / 普通话 / 含项目介绍 + 核心功能演示 + AI 技术亮点**
> 目标时长 **7:10**（安全区间 6:40–7:20），正文口播约 1650 字，按 240 字/分钟实测可落位。
> 本文替代 `02-录屏脚本.md`。旧版主片按 5 分钟写、投稿片 2:59——**3 分钟片低于 5 分钟下限，不能作为主演示视频提交**，只建议当补充素材或答辩备用。

## 一、这一版改了什么

| 旧版的问题 | v2 的处理 |
|---|---|
| 3 分钟投稿片不满足 5–8 分钟要求 | 重写为 7:10 单片，不再做"5+3+8"三套并行 |
| 按产品卖点组织，AI 只占 1 分钟 | 按赛项三大必含内容重排：**项目介绍 0:20–1:10 / 核心功能 1:10–3:30 / AI 技术亮点 3:30–6:20** |
| 没对着评分表设计 | 每段标注对应评分项，文末附「评分表 → 镜头」对照与现状自评 |
| 讲了不少"我们做了什么"，没讲"为什么这么做" | 每个 AI 环节都补一句取舍理由（评委 35% 那栏看的是判断力，不是功能清单） |
| 容易吹到没实现的能力 | 全片不出现 RAG、流式、MCP、TypeScript、多 Agent——**这些当前代码里没有**，念了就是答辩风险 |

一句话定位：**这不是功能宣传片，是给评委看的 7 分钟技术答辩预演。**

>
> 但它其实是这瓶东西上最诚实的一部分——法规要求，成分必须按含量从高到低排列。

**字幕**

- 法规要求：按含量从高到低

**评分点**：选题创新（真实、具体、一句话能复述）。

### S1 ｜ 0:20–1:10 ｜ 项目介绍：不是查字典，是读结构

**画面**
- 切首页全景；0:20–0:23 左下角浮出信息条：`成分镜 ｜ AI Web 开发挑战赛 ｜ 本科 B 组 ｜ 队名`，三秒后淡出。
- 首页停留 2 秒，不要动鼠标。

**口播**（约 205 字）
> 我们叫它成分镜。它只做一件事：把这串没人读完的小字，翻译成一句和你有关的结论。
>
> 市面上大多数产品做的是查字典——识别成分、逐个查百科、给一个总分。但那不产生新信息，还会给出一个对所有人都一样的分数。
>
> 成分镜换了个思路：成分按含量降序排列，这个顺序本身就是配方结构。谁能排进前五位，谁只是名字印在正面，是可以推出来的。
>
> 同一瓶东西，油皮和干皮、孕期和不是孕期，结论可以完全相反。所以我们先问你三个问题，再回答你。

**字幕**
- 不查成分百科，读配方结构
- 同一瓶，对不同的人结论不同

**评分点**：选题创新 10%、实用性 5%（问题定义清晰）。

### S2 ｜ 1:10–1:40 ｜ 入口：把"我该点哪"这件事做掉

**画面 / 操作**
1. 指三个入口：粘贴、拍照、示例。
2. 点「示例 · 美白精华液」→ 产品名自动带入。
3. 鼠标停在输入框底部左侧的「14 字 · 14 个成分」，以及下方「将分析」的成分标签上（数字以屏幕为准，跟着念）。
4. 右侧档案保持「油性 · 敏感肌」。
5. 点「开始解读」。

**口播**（约 118 字）
> 入口有三个：粘贴成分表、拍照识别，或者直接用内置示例。
>
> 粘贴的时候，输入框下面实时告诉你这一串会被切成几个成分。切错了当场就能看到，不用等报告出来才发现。
>
> 右边是档案：肤质、是否敏感、是否孕期。这三项不是装饰，它们决定了后面风险的排序。

**字幕**
- 实时切分：切错了当场看见
- 档案决定风险排序

**评分点**：UI 设计 4%、交互体验 3%。

### S3 ｜ 1:40–2:30 ｜ 报告：把顺序翻译成结论（核心镜头）

**画面 / 操作**
1. 报告出现，停在结论卡 3 秒（等级、标题、档案）。
2. 滚到「配方梯队」，鼠标沿前 5 / 6–10 / 11 位之后三档缓慢移动。
3. 指「烟酰胺」在第 12 位，停 2 秒。
4. **点烟酰胺胶囊**，弹出成分详情卡：角色、深度描述、风险、第 12 位、别名。
5. 关闭详情卡。

**口播**（约 198 字）
> 报告第一屏只给一个结论，不给你十个指标。
>
> 往下是配方梯队：前五位、六到十位、十一位之后。这三个区间不是我们划的，是含量递减推出来的。
>
> 这瓶主打烟酰胺美白。你看，烟酰胺在第十二位。它前面还有十一个成分，按递减规则，它大概率不到百分之一。名字印在正面，含量排到后面——这就叫概念添加。
>
> 点开任何一个成分，能看到它在这瓶里的排位、作用、风险和别名。不是一张孤立的成分百科，是这一瓶里的成分。

**字幕**
- 三档梯队 = 含量递减
- 第 12 位 ≠ 主功效
- 点成分 → 看它"在这瓶里"的位置

**评分点**：技术方案创新 8%（把法规排序变成可计算结构）、AI 交互 3%（点击即上下文）。

> **录前核对**：示例 1 里烟酰胺确实排第 12（水、甘油、丙二醇、丁二醇、1,2-戊二醇、透明质酸钠、泛醇、卡波姆、氢氧化钠、苯氧乙醇、羟苯甲酯、烟酰胺）。**口播数字永远跟着屏幕走**，改了配方就改口播。

### S4 ｜ 2:30–3:05 ｜ 个体化：报告页里直接改，不跳页

**画面 / 操作**
1. 报告顶部点「调整档案」。
2. 关闭「敏感肌」→ 报告就地重算 → 指变化提示「风险成分 6 → 2」。
3. 再打开「敏感肌」恢复。
4. 切「示例 · 抗老紧致面霜」，打开「孕期/备孕」。
5. 指「孕期建议避开：视黄醇」。

**口播**（约 132 字）
> 同一瓶东西，结论可以完全反过来。关掉敏感肌，需要留意或避开的成分从【6】个降到【2】个。变化直接写在报告里，不用你自己对比两份。
>
> 换一瓶抗老面霜，勾上孕期，视黄醇直接进"建议避开"。
>
> 这一条不是模型猜的，是写在规则里的硬约束。我们很清楚：哪些可以交给模型，哪些不能。

**字幕**
- 原地重算，不跳页
- 风险 6 → 2，变化直接说
- 规则判定，不靠模型猜

**评分点**：交互创新 7%、AI 可控性 4%（引出下一段）。

> `【6】`/`【2】` 是**实时读数**，以屏幕显示为准，不要背死数字。

### S6 ｜ 3:30–4:05 ｜ AI 亮点①：一张模糊照片 → 结构化成分

**画面 / 操作**
1. 回输入页，点拍照入口，上传一张真实包装（弧面、反光、字号小）。
2. 识别中状态停 2 秒（不要剪成瞬间完成，评委要看得到"在处理"）。
3. 结果填入，产品名自动填入输入框。
4. 指「已识别出 N 个成分，产品名「…」已自动填入」这行提示。
5. 若识别把空格当分隔符：点「按空格切分」一键修复。

**口播**（约 140 字）
> 接下来是 AI 的部分。第一个位置：把一张模糊的照片，变成结构化的成分文本。
>
> 包装是弧面的、会反光、字号又小，传统 OCR 在这种图上基本失效。我们用视觉大模型做结构化抽取，提示词只允许它输出成分名、用顿号分隔——不让它自由发挥。
>
> 如果它把空格当成了分隔符，这里有一键修复，不用整段重打。

**字幕**
- 图像进，结构化文本出
- 提示词只准输出成分名
- 识别错了 → 一键修复，不用重打

**评分点**：多模态 5%、大模型集成质量 8%（提示词约束）。

> **降级方案**：录前视觉 Key 不可用，就只录粘贴路径，本段改成 5 秒画中画（标注"测试环境实录"），并把 S6 口播压到 60 字。**不要录报错，也不要把没跑通的识别说成跑通了。**

### S7 ｜ 4:05–5:00 ｜ AI 亮点②：判定归规则，生成归模型

**画面 / 操作**
1. 编辑器打开 `VisionService`，字号 20pt 以上，停 6 秒：系统提示词「只输出成分名，用顿号分隔，看不清就只输出『看不清』」。
2. 切 `ResearchService`，停 5 秒：`temperature 0.1`、`max_tokens 900`、提示词里的「不要编造法规限量」「confidence 0–1，只输出 JSON」。
3. 切 `AnalyzeService`，指规则部分（限量、禁忌、梯队）。
4. **造一个全未识别的输入**（如「甲乙丙、丁戊己」）→ 报告显示「未能解读」，不是绿色「可以放心」。停 3 秒。
5. 回原报告。

**口播**（约 220 字）
> 模型只做两件事：把像素变成文本，把没收录的成分补成结构化条目。看不清的图，它只准回"看不清"，不准猜；没把握的成分，得把置信度和依据一起交出来。
>
> 判定——限量、禁忌、排在第几位——全部由确定性规则完成。原因很直接：概率模型不可审计。孕期的禁忌给错一次，就没有第二次机会。
>
> 还有一个我们特意做的兜底。如果整份成分表一个都没认出来，界面不会显示绿色的"可以放心"，而是"未能解读"；覆盖率不到一半，就降级成"信息不足"。
>
> 认不出来，不等于安全。这是这类工具最容易犯、也最危险的错。

**字幕**
- 感知与表达交给模型
- 看不清就回"看不清"，不准猜
- 限量 / 禁忌 / 排位交给规则
- 认不出来 ≠ 安全

**评分点**：AI 安全与可控性 4%（本片最扎实的一段）、技术方案创新 8%。

> **操作细节**：录这一镜前，去控制台把「研究 API」Key 清空并保存，避免未识别词被后台研究掉、报告中途翻转；录完恢复。否则「未能解读」可能在你讲到一半时变成有结论。

### S8 ｜ 5:00–5:50 ｜ AI 亮点③：研究队列 = 带人工闸门的工作流

**画面 / 操作**
1. `#/admin` →「研究任务」：指一条已完成任务——原始名 `(日用)香精`，结果 `香精`，依据「已合并为已有成分的别名」。
2. 进「成分数据」→「待研究」页签：指置信度、依据、AI 深度描述列。
3. 勾一条 → 点确认 → 状态变「已确认」。
4. 回 `#/ingredients` 搜「水」，指 AI 深度描述与「AI 深度研究」标记。
5. 回报告，点「水」的详情卡，指同一段描述。

**口播**（约 208 字）
> 第二个位置：成分库不可能一开始就收全。没收录的成分，不会悄悄丢掉。
>
> 扫描时没命中的词，先进研究任务队列；后台 worker 领走，调模型，要求返回结构化 JSON——标准名、作用、风险、限量，还要带置信度和依据。
>
> 比如"(日用)香精"，模型把它归一成"香精"。它不是新建一条重复数据，而是自动并成已有成分的别名，下次扫描直接命中。
>
> 研究成功也不等于生效。结果先回到"待研究"，报告里标注 AI 补全，人工确认之后才转成"已确认"。失败会留下任务、错误和重试按钮——不会把没研究出来，伪装成成功。

**字幕**
- 未收录 → 研究队列 → 自动研究
- JSON + 置信度 + 依据
- 括号变体自动并别名
- 先待研究，人工确认后才生效
- 失败可重试，不假装成功

**评分点**：Agent/工作流 8%（任务队列 + 自动重试 + 人机闸门）、大模型集成质量 8%（结构化输出约束）。

> 录音前把失败任务重试或删掉，只录"已完成"。**不要在现场等模型**。

### S9 ｜ 5:50–6:20 ｜ AI 亮点④：为什么我们不用向量检索

**画面**
- README 的两段工程决策，或一张架构图；
- 叠字并排：`羟苯甲酯 / 羟苯丙酯`、`1,2-丙二醇 / 1,2-戊二醇`。

**口播**（约 105 字）
> 成分匹配，我们明确不用向量检索。
>
> 羟苯甲酯和羟苯丙酯，在向量空间里几乎重合，但一个是常规防腐剂，一个孕期要谨慎——混淆就是安全事故。
>
> 所以我们走标准名、别名、包含匹配；编辑距离只对纯英文名开放。中文名宁可判"待补全"，也不张冠李戴。

**字幕**
- 向量相近 ≠ 安全相近
- 标准名 → 别名 → 包含匹配
- 中文名不做模糊匹配

**评分点**：技术方案创新 8%、RAG 取舍（有判断、但**不宣称实现了 RAG**）。

> 这段是全片最容易被记住的"技术判断力"镜头。别为了凑 RAG 分数硬说"我们有 RAG"——一被追问检索策略就穿。

### S10 ｜ 6:20–6:50 ｜ 工程质量：能被别人接手

**画面 / 操作**
1. 编辑器展开 `web/src/components` 目录树（20 个组件），滚一遍。

## 八、后期与导出

**录音方式**：先定稿口播 → 单独录音 → 再按音轨剪画面。边操作边讲最容易出现"讲完了鼠标还没到"。

**节奏**：每 4–8 秒要有一个画面变化；纯等待（识别中、加载中）保留 1–2 秒即可，别超过 3 秒。

**字幕**：简体硬字幕，每行 ≤18 字，专有名词逐个校对：**成分镜 / 烟酰胺 / 视黄醇 / 羟苯甲酯 / 羧…（按实际出现）**。

**导出参数**
```bash
# 统一到 1080p30、H.264、AAC，响度 -14 LUFS
ffmpeg -i raw.mov \
  -vf "scale=1920:1080:flags=lanczos,fps=30" \
  -c:v libx264 -profile:v high -crf 18 -preset slow -pix_fmt yuv420p \
  -af "loudnorm=I=-14:TP=-1.5:LRA=11" \
  -c:a aac -b:a 192k -ar 48000 -ac 2 \
  -movflags +faststart out.mp4
```

**交片前核验**
```bash
ffprobe -v error -select_streams v:0 -show_entries stream=width,height -of csv=p=0 out.mp4
ffprobe -v error -show_entries format=duration -of csv=p=0 out.mp4
```
分辨率必须是 `1920,1080`，时长必须在 300–480 之间。
