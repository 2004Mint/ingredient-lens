## 2. 结构性缺口（按丢分从大到小）

### 缺口 A：RAG = 0 分，且是一个"自己写死"的失分

`README.md:395` 主动声明"成分匹配绝对不用向量检索"。**这个工程判断本身是对的**（`1,2-戊二醇` vs `1,2-丙二醇` 向量确实会混），但评委看到的是"选手主动放弃了 6% 的 RAG 考察点"，而且方案书 `5.2` 里承诺的"检索到成分条目与法规原文后由模型组织说明"并没有实现。

**正确做法不是改匹配，而是把"检索"和"匹配"分开**——这是答辩时一句就能说清的技术叙事：

| 用途 | 技术 | 理由 |
|---|---|---|
| 实体识别（这瓶里有什么） | 精确名 → 别名 → 包含匹配（现有） | 安全，不能容错 |
| 知识检索（依据哪条法规、同类成分怎么说、用户追问怎么答） | **BM25 + 向量混合检索，返回带 `source` 的片段** | 允许模糊，需要召回 |

也就是说：**匹配不向量化，知识检索必须向量化。** 这不是妥协，是分层。

### 缺口 B：Agent 只有"队列"，没有"规划 + 工具"

现在 `ResearchTaskWorker` 是"未收录成分 → 调一次模型 → 写库"。它证明了你懂异步与重试，但评分细则问的是"是否具备规划、工具调用、自主决策能力"。**一个不调用工具的循环不叫 Agent。**

成本最低的改法：把已有的三个能力注册成工具，让一个"分析 Agent"编排它们——`lookup_ingredient` / `lookup_regulation` / `compare_formulas` / `explain_report`，用户说"我孕期，帮我看看这两瓶哪个更稳"，Agent 自主决定先查谁、要不要补查、要不要反问。前端把 plan/tool trace 画出来，交互创新那 7% 也一起拿了。

### 缺口 C：LLM 没参与"主结论"，AI 是装饰

方案书 `5.1` 自己立的 flag——"结论 → 人话：模板可做，质量有限 ✅ 语言模型"——**代码里没有**。`AnalyzeService` 的 `summarize()`/`buildInsights()` 全是字符串模板，整个 `/api/analyze` 路径不碰模型。评委一旦抽查，会发现这个"AI 应用"的核心链路是确定性的，AI 只在管理后台跑。

这是"AI 技术深度"和"技术方案创新"同时失分的地方，也是**投入产出比最高的一处**：加一个生成式解释层 + SSE 流式，两天见效。

### 缺口 D：多模态只有一进一出

VLM 读图算一条，但评分要的是"多种模态（文本、图像、语音、视频），融合是否自然"。语音输入（Web Speech API，零成本）＋ 语音播报（已有的 Breeze-TTS 流水线可复用）就能把"多模态"从 1 条扩到 3 条，还能顺带做无障碍。

### 缺口 E：MCP 与工具集成 4 分整块空着

赛项把 MCP 写进了时代背景，评委预期至少有"我接了 MCP"的证据。把成分库查询 + 法规查询封成一个 stdio MCP Server（Node 或 Java 都行，200 行内），在技术文档放一张 Claude Desktop / 自研前端调用 MCP 的截图，就是 4 分里能拿到的 2–3 分。**这是全项目最便宜的分数。**

### 缺口 F：前端工程质量有 4 分是"硬扣"

细则原文是"**TypeScript 规范使用**"。现在 `web/package.json` 只有 `vue` 一个依赖，全 JS。评审看到 `TypeScript 未使用` 会直接扣，不需要读代码。同时没有 ESLint/Prettier/tsconfig，也没有路由懒加载——管理台 1037 行 CSS 跟着首屏一起下发。

## 6. 答辩必被问到的 10 个问题（提前写答案）

1. **"你们的 AI 到底做了什么不可替代的事？"** — 现在只能答"读图和填库"，这是最危险的一问。做完 P0-1/P0-3 后答案变成：感知（VLM）+ 检索（RAG）+ 编排（Agent）+ 表达（LLM），规则只做不可让渡的安全判定。
2. **"为什么不做向量检索？"** — 三段式：实体匹配不能容错（举 `1,2-戊二醇` 实例）→ 但知识检索必须模糊召回 → 所以我们做两层，匹配用规则、检索用混合索引。
3. **"模型编造法规限量怎么办？"** — 已有答案（先待研究、人工确认、confidence/evidence、不确定留空），再加输出侧校验：限量字段必须命中法规表才允许展示。
4. **"为什么用 Java 后端？前端 AI 集成在哪？"** — 说明取舍：判定与密钥管理放服务端更安全；但必须补前端侧的流式渲染、端侧检索或语音，否则"前端为主"的定位站不住。
5. **"60 条成分够吗？数据准吗？"** — 扩库 + 每条来源 + 抽检准确率。
6. **"和美丽修行/透明标签有什么不同？"** — 差异在"位置→含量"的推理与个体化重排，不是又一个成分查询库。
7. **"商业模式？"** — 现在没有答案，至少准备：C 端免费 + B 端成分合规 API + 品牌配方自检。
8. **"医疗合规边界？"** — 已有免责声明，补"不评价商品优劣、不做诊断"的产品级约束。
9. **"性能数据？"** — Lighthouse、首屏 chunk、接口 P95，现在一个都没有。
10. **"模型挂了还能用吗？"** — 已有降级设计，这是加分项，要主动讲。

## 7. 明确不建议做的事

- ❌ **把实体匹配改成向量检索**：会引入 `丙二醇/戊二醇` 类误判，答辩必被问死，且与现有可信度设计冲突。
- ❌ **加一个通用聊天框充当"AI Agent"**：方案书自己写了"不为了融资故事堆砌 AI 聊天"，评委一眼看穿。
- ❌ **重写 Git 历史伪造开发过程**：不如用剩下 18 天真实小步提交，评委看的是"最近有没有持续迭代"。
- ❌ **为了凑多模态塞视频生成**：成本高、与场景无关，反而稀释叙事。
- ❌ **只改文档不改代码**：现在方案书 `5.1/5.2` 承诺的"LLM 生成解释""检索法规原文"都没实现，文档与代码不一致是评审最反感的失分点——**要么实现，要么改文档口径**。

## 8. 结论

- **保底动作**（1 天，纯材料）：PDF、团队信息、`.env.example`、远端仓库、分批提交 → 避免"材料不完整"直接降档。
- **冲奖动作**（10 天，P0）：生成式解释 + RAG + Agent + MCP + 在线演示 → AI 深度从 13/35 提到 26/35，总分进入 68–72。
- **拉开差距的动作**（P1）：TS、懒加载、语音、评测集、300+ 带来源成分库 → 工程质量与"有数据支撑"的评审印象。

一句话：**这个项目的产品直觉已经够了，缺的是把"AI 用在核心链路上"这件事做出来，并且让评委在 5 分钟内看得见。**
