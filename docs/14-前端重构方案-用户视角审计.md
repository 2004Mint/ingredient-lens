## 0. 一句话诊断

**问题不是"文字太多"，是"没有层级"。** 规则引擎的中间产物被原样平铺：梯队、风险分组、功效定位、发现、法规、统计——六种"证据"和"结论"平级出现，用户必须自己从 8 屏里拼出一句话。

一个能说明问题的细节：首页从标题到 CTA，中间有 **11 处**辅助文字（`成分表 · 位置即含量`、3 条能力标签、`第一步/第二步`、`59 字 · 14 个成分`、`顿号 / 逗号 / 换行都可以`、`将分析（14 个 chip）`、`没有实物？`、三张示例卡各 2 个标签、`将按「油性、敏感肌」解读`、`1 秒内出结果 · 规则引擎判定，不调用生成式模型`）。用户要做的事只有一件：**把成分表给我**。

## 2. 用户与任务模型

### 2.1 三类真实用户

| 用户 | 场景 | 真正的诉求 | 成功标准 |
|---|---|---|---|
| **A. 货架前的敏感肌** | 手机、单手、店里光线差 | 这瓶我能不能用？哪个成分要躲？ | 30 秒内看到"要避开的 1 个" |
| **B. 下单前的比较者** | 电脑、开着购物页 | 两瓶哪个更适合我？ | 结论可并排对比 |
| **C. 内容创作者** | 电脑、要出稿 | 这话能不能引用？依据在哪？ | 一条结论能找到一条依据 |

### 2.2 五种任务（按频次）

1. **首次试（最高频）**：粘贴 → 选档案 → 看结论
2. **复访查**：打开历史 → 看上次那瓶
3. **现场拍**：拍照 → 确认识别 → 看结论
4. **改档重算**：同一瓶，换成孕期/敏感肌再看
5. **分享/引用**：生成链接或复制结论

> 设计含义：**1 和 3 必须一屏内完成**；4 必须在结论页原地完成；5 是出口，不该占主流程。

## 3. 三条主使用动线（重构后）

### 动线 A｜首次试（桌面，目标 60 秒出结论）

```
落地 ──→ 看到一句话价值主张 + 一个输入框（首屏唯一焦点）
       └→ [可选] 点"看一个例子"→ 直接看到完整报告长什么样（30 秒建立预期）
输入成分表 ──→ 实时显示"切出 14 个成分"（一行，不打扰）
              └→ 有异常才出现提示（分隔符识别失败）
选档案 ──→ 3 个 chip：干/油/混 · 敏感 · 孕期（默认折叠细节）
点"解读" ──→ 1 秒出结论
            └→ 首屏只给：结论 + 3 个数字 + 3 条理由（各一行）
展开任一条理由 ──→ 就地展开依据（成分、位次、限量）
```

**砍掉的摩擦**：右栏主 CTA（改为全宽粘底）、示例卡（改为一行文字链接）、能力标签（改为标题下方一句副文案）、统计四联卡（并入结论条）。

### 动线 B｜货架前（手机，目标 20 秒）

```
打开 → 底部 tab「解读」→ 相机按钮（首屏右下，拇指区）
     → 拍照 → 识别结果确认（成分表可编辑，一行提示"识别到 14 个"）
     → 结论条（吸顶）：需要留意 · 1 个要避开
     → 只展开"要避开的"那一组 → 看到成分名与一句话
```

**关键决策**：移动端**不做多页报告**，结论页就是全部；梯队图折叠成三行摘要，点开才全屏看。

### 动线 C｜改档重算（桌面 + 手机）

```
结论页 → 顶部档案 chip（如「油性 · 敏感」）→ 点开浮层改档
      → 就地重算 → 结论条下方出现"风险 6 → 2"的变化说明
```

**保持你已有的优点**：不跳页、保留旧结论、说明差异。这块设计是对的，重构只改视觉与位置。

## 4. 信息架构（IA）

```
成分镜
├─ 解读（默认）
│   ├─ 输入台（首页）
│   └─ 报告
│       ├─ 结论层（首屏，默认展开）
│       ├─ 理由层（3–5 条，可展开）
│       └─ 证据层（折叠：梯队 / 功效 / 未识别 / 法规）
├─ 成分库（搜索优先）
├─ 怎么算的（原"方法"+"关于"合并 = 信任页）
├─ 历史（桌面：抽屉；移动：tab）
└─ 管理台（后台，不进主导航）
```

**合并逻辑**：`方法` 与 `关于` 合并为「怎么算的」——用户问的是同一个问题"我凭什么信你"。`分享/反馈` 放进报告页与信任页的末尾，不占主导航。

## 6. 视觉系统重构

### 6.1 配色（保留基因，收紧用法）

保留纸感底 + 墨色 + 玉绿；**只改用法，不换风格**。

| Token | 值 | 用途 | 对比度 |
|---|---|---|---|
| `--bg` | `#F4F1E9` | 页面底 | — |
| `--surface` | `#FFFFFF` | 卡片 | — |
| `--ink` | `#1A1713` | 主文本、大标题 | 15.8:1 ✅ |
| `--ink-2` | `#55504A` | 次文本 | 7.2:1 ✅ |
| `--ink-3` | `#6B655A` | 辅助文本（**由 #736D62 加深**） | 4.9:1 ✅ |
| `--line` | `#E6E0D3` | 分隔、描边 | — |
| `--brand` | `#1F6B5A` | 主按钮、链接、强调 | 5.3:1 ✅ |
| `--brand-ink` | `#144C40` | 按钮 hover、深色文字 | — |
| `--brand-soft` | `#E5F0EA` | 选中态底 | — |
| `--danger` | `#A93A2B` | 只用于「建议避开」 | 6.1:1 ✅ |
| `--warn` | `#8A5A12` | 只用于「需要留意」（**加深**） | 5.4:1 ✅ |
| `--good` | `#2F7F5D` | 只用于「没有明显风险」 | 4.6:1 ✅ |

**三条新规则**：
1. **纯黑不再出现**。首页那个 `#000` 主按钮改为 `--brand`（现在全站只有它一个黑色元素，与玉绿体系打架）。
2. **语义色只给结论与风险**，不用于装饰、图标、标签底色以外的场景。
3. **同一屏最多一个实心按钮**；其余一律 ghost 或文字链接。

### 6.2 字号阶梯（32 → 8 级）

| 名称 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| `display` | 40 / 48 | 600（衬线） | 仅首页 H1 |
| `h1` | 28 / 36 | 600（衬线） | 报告结论标题 |
| `h2` | 22 / 30 | 600 | 页面区块标题 |
| `h3` | 17 / 26 | 600 | 卡片标题 |
| `body` | 15 / 26 | 400 | 正文 |
| `body-s` | 13.5 / 22 | 400 | 卡片说明、表单值 |
| `caption` | 12 / 18 | 500 | 标签、meta |
| `micro` | 11 / 16 | 600 + 字距 .08em | 全大写标签、单位 |

删除所有 8.5–11.5px 的碎片字号（现在共 147 处），统一落到 `caption` / `micro`。

### 6.3 间距 / 圆角 / 阴影

- **间距**：4 的倍数，只用 `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`；卡片内边距 20–24，区块间距 32。
- **圆角**：`--r-card: 12`、`--r-control: 10`、`--r-pill: 999`。现在全站 16px 偏"软"，层级反而模糊。
- **阴影**：只留两级（卡片 / 浮层）；平面区域用 1px 描边，不叠阴影。
- **描边**：卡片 1px `--line`，选中 1px `--brand`；不再用 2px 边框做大面积分隔。

### 6.4 断点（9 → 3）

| 名称 | 范围 | 策略 |
|---|---|---|
| `mobile` | < 640 | 单列、底部固定 CTA、tab 导航 |
| `tablet` | 640–1023 | 单列加宽（720 内容宽）、CTA 内联 |
| `desktop` | ≥ 1024 | 双栏（正文 + 320 侧卡） |

移动优先书写：先写 mobile 规则，再用 `min-width` 覆盖。

## 7. 组件与密度规则

### 7.1 组件清单（重组后约 14 个）

```
atoms      Button / Chip / Tag / Divider / IconButton / Skeleton
molecules  VerdictBar（结论条）/ ReasonCard（理由卡）/ ProfilePicker（档案行）
           InputCard（输入卡）/ SampleLink / SourceNote（依据脚注）
organisms  ReportSummary（结论区）/ EvidenceSection（可折叠证据区）
           LadderSummary（三行梯队）/ RiskGroupList / NavBar / BottomTabs
templates  IntakePage / ReportPage / LibraryPage / TrustPage
```

删除：`AnimatedNumber`（数字动画在结论页是干扰）、锚点导航条、`ProfilePanel` 独立卡（并入档案行）。

### 7.2 密度硬规则（写进评审标准）

1. **每屏一个主 CTA**。
2 . **首屏文本块 ≤ 3**：标题、一句解释、主操作。其余进折叠或下一屏。
3. **同一条信息只出现一次**：结论不在三处重复（结论卡、统计卡、摘要）。
4. **meta 文本不与主操作同行**：`59 字 · 14 个成分 · 顿号/逗号` 这类只保留一个数字（"14 个成分"）。
5. **折叠默认态**：超过 3 项的列表一律默认收起，标题带数量（`配方结构（14）`）。
6. **卡片不嵌套**（现在示例卡嵌在输入卡里）。

## 10. 明确不建议做的

- ❌ **换风格**：纸感 + 墨 + 玉绿这套基因是资产，问题在层级不在配色。
- ❌ **加深色模式**：赛项不加分，且会翻倍样式工作量。
- ❌ **加动效/插画**：当前是"密度"问题，不是"缺乏生气"问题，加动效只会更吵。
- ❌ **做仪表盘式统计**：用户不需要"14 个成分 / 4 个功效"这样的 KPI 墙。
- ❌ **在 11/18 前全量重写组件**：回归风险高，且作废已录素材。

### 从这 4 个画面提炼出的 6 条新规则（给实现用）

1. **覆盖率 < 50% 时不允许出现结论等级色**（绿/黄/红），一律用中性卡片 + "信息不足"。
2. **未识别成分永远占位**（虚线 + 序号），且永远不出现在"可以放心"的语境里。
3. **加载中不展示空折叠**：折叠区显示"等待中"，避免用户点开一个空壳。
4. **成分库一行只表达 4 个信息**；超过 4 个就说明这一行放错了东西。
5. **搜索框是成分库唯一的主操作**，筛选是辅助；不做"按热度/按字母"这类二级排序入口。
6. **设计系统板是唯一裁决处**：任何新页面出现第 9 种字号、第 4 个断点，都视为 bug。

## 12. 视觉 v3：把「纸」做成「纸上仪器」（2026-11-12 深夜）

第 11 节的 8 个画面被评审为「结构对了，但看着太简单」。诊断如下：

- 全站只有一种字体层级（无衬线），标题和正文靠字号拉开，缺少**字体的性格**；
- 所有卡片都是 1px 灰边 + 12px 圆角，**没有材质、没有仪器感**；
- 产品最核心的洞察（位置即含量）**没有任何图形**，只存在于文案里；
- 全站没有一个"只能属于成分镜"的视觉符号，去掉 logo 就和任意文档站一样。

### 12.1 方向：米色的纸 + 黄铜的刻度 + 墨绿的结论

不是换风格，是把原有的纸感基因往前推一步：**把"检测报告 / 标本卡 / 尺"的隐喻做进结构里**，而不是加装饰。

| 层 | 作用 | 做法 |
|---|---|---|
| 纸 | 底 | 三层纸色（paper / paper-2 / surface）+ 极淡噪点（feTurbulence，opacity .5，multiply） |
| 铜 | 刻度与仪表 | 只用于：透镜标铜圈、尺的刻度与标记点、卡片四角校准角、眉题小字 |
| 墨绿 | 结论与动作 | 主按钮三段渐变、正文强调、印章主色 |
| 朱红 / 琥珀 / 苔绿 | 风险三档 | 只出现在结论与标签，不参与装饰 |

> 关键约束：**黄铜是 1px 级别的辅色**。一旦它变成大色块（黄色卡片、金色按钮），这套语言就崩了。

### 12.2 字体：换成可以拉出层级的组合

| 用途 | 字体 | 理由 |
|---|---|---|
| 标题 / 数字 / 印章 | **Noto Serif SC**（回退 Source Han Serif / 思源宋体） | 有真宋体的笔画对比，比 SimSun 干净；数字用 `font-variant-numeric: tabular-nums` 对齐 |
| 正文 / 控件 | **Noto Sans SC** | 与宋体同源，字面率接近，混排不打架 |
| 编号 / 参数 / 英文眉题 | **Cascadia Mono** | 让"014 / PASTE / DOSE BY POSITION"这类元信息一眼区别于正文 |

实现提示：`font-family` 里把 `"Noto Serif SC"` 写在 `"Songti SC"` 之前——macOS 上落到 Songti，Windows 上落到 Noto Serif，两边都不掉到系统默认宋体。

### 12.3 四个签名组件（缺一个就不像这个产品）

1. **Lens 透镜标**：铜圈 + 纸面 + 宋体「镜」，替代"圆形字母底"。用在导航与页脚。
2. **Seal 印章**：圆形双环 + 一个汉字（避 / 慎 / 待补），旋转 -9°，压在结论卡右上角并轻微越界。**它是全站唯一"有情绪"的元素**，用来说明结论的确定性。
3. **Ruler 位置尺**：横轴 1–N 刻度，前/中/后三段分区，标记点落在真实排位上。首页讲原理、报告页标冲突项、系统板做规范示例。**全站只有一个数据图形，就是它。**
4. **Specimen 样本卡**：左侧打孔纸条 + 竖排编号（`SPECIMEN 014`），把"一份检测报告"的隐喻做进结构，不额外加装饰。

### 12.4 版式上的四个动作

- **两栏工作台**：文案 5 / 输入卡 5，取代原来的居中 720px 单列——首屏有构图，不是一条竖排；
- **版心外边注**：≥1360px 时左侧留一条竖排边注（`Ingredient Lens · 成分镜 · 2026`），书页感；
- **结论卡横跨正文栏**：报告页顶部是一条"标本卡"而不是普通卡片，印章越界打破网格；
- **页脚墨绿书挡**：米色页面用一个深色收口，避免整页"飘"。

### 12.5 与新规则的一致性检查

第 11 节的 6 条规则全部保留，另加 4 条：

7. **黄铜只做 1px**：线、圈、角标、小字。出现金色块状填充即为超纲。
8. **一个页面只有一个印章**：印章 = 结论确定性，多个印章等于没有结论。
9. **尺的刻度必须真实**：刻度数 = 成分数，标记点位置 = 真实排位，不允许"示意性"地画几根线。
10. **Noto Serif 只给标题与数字**：正文一律无衬线，否则长文本在 15px 下发糊。

### 12.6 这轮**没有**解决的事（别误判）

- 仍然**只是静态设计稿**，`web/src` 一行未改；
- 只是把"简单"变成"有语言"，**信息层级问题仍是第 11 节那 6 条规则在管**；
- 动效、插画、深色模式依然不做（理由见第 10 节）；
- 落地仍建议按 P0（结构）→ P1（视觉 token）两段走，全量换视觉会作废已录视频与 6 张截图。
