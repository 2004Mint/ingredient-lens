# 成分镜 · 产品化清单（v1.0）

> 视角：项目经理。目标不是再加一个功能，而是把「能演示的原型」变成「看起来有人在运营的产品」。
> 日期：2026-10-30　｜　对应版本：v1.0.0

---

## 一、之前为什么像 demo

| 信号 | 之前的状态 | 用户 / 评委的感受 |
|---|---|---|
| 产品外壳 | 单页表单 + 页脚免责声明 | 像一个工具页，不像一个产品 |
| 报告 | 看完即走，没有编号、时间、产品名 | 无法保存、无法引用、无法分享 |
| 内容纵深 | 只有 60 条成分，但没有任何地方能查 | 数据是黑盒，可信度靠嘴说 |
| 信任 | 没有数据来源、规则版本、更新日期、隐私说明 | 不敢把孕期信息填进去 |
| 失败体验 | 视觉错误直接把上游 503 JSON 甩给用户 | 一眼 demo |
| 运营闭环 | 没有反馈入口、没有版本、没有管理控制台 | 出问题只能找你本人 |
| 工程 | 没有测试、没有版本/健康接口、没有部署说明 | 不敢改，也不敢交给别人 |

结论：**用户看到的不是「功能少」，而是「没有产品的骨架」**——没有导航与内容体系，没有可沉淀的报告资产，没有可信度与运营闭环。

## 二、v1.0 本轮交付

| 模块 | 交付 | 验收标准 |
|---|---|---|
| 产品外壳 | 顶部导航（首页 / 成分库 / 方法 / 历史 / 关于）、页脚导航、版本号、PWA manifest、OG 分享图 | 任意页面都能回到三个核心区；分享到聊天有标题与封面 |
| 报告资产化 | 产品名、分析编号、生成时间、规则库版本；本机历史（最近 20 份）；短链接分享 | 刷新不丢历史；链接可被另一台设备打开；分享页有隐私提示 |
| 内容纵深 | 成分库页面（60 条，搜索 / 角色 / 风险筛选）；解读方法页；关于与隐私 | 成分库可查到烟酰胺、孕期禁忌、限量；方法页能解释每条结论的依据 |
| 信任层 | 数据来源、库版本、更新时间、能力边界、隐私与免责声明、可信度降级 | 报告、方法页、关于页三处口径一致；「未识别」不显示绿色「可以放心」 |
| 运营闭环 | 管理控制台（登录、概览、总/视觉/研究 API、成分待研究-已确认-已拒绝、AI 研究、**研究任务队列**、分享报告、反馈、系统状态）；本机反馈存储；分享 30 天清理 | 换模型不重启；未收录 token 先入队、后台自动研究、失败可重试；AI 结果先待研究再人工确认；成分改完立即生效；分享可删除 |
| 工程底座 | 后端规则引擎回归测试（7 个用例）；`/api/version`、`/api/health`；构建与运行说明 | `mvn test` 通过；版本号单一来源；新同学能按 README 跑起来 |

### 已落地的关键交互

- **报告不是一次性页面**：有产品名、编号、时间、规则版本；可以改名、进历史、生成短链。
- **成分库不是装饰**：60 条真实数据可搜索、可筛选，和报告里的「未收录」形成互补。
- **失败不是死路**：拍照失败给「重试 / 改用粘贴」；分享失败给「复制报告全文」；视觉模型不可用时给可行动的中文原因。
- **数据只在本机**：历史在 localStorage；分享报告、反馈、管理配置在 `server/data/`，都已 gitignore。

## 三、产品指标（内测版定义）

| 指标 | 目标 | 采集方式 |
|---|---|---|
| 激活率 | 首页 → 点击开始解读 ≥ 60% | 本机事件或人工观察（当前不做第三方追踪） |
| 完成率 | 开始解读 → 报告生成 ≥ 90% | 同上 |
| 资产化率 | 报告进入历史或被分享 ≥ 25% | 历史条数 / 分享次数 |
| 内容渗透 | 访问成分库或方法页的 session ≥ 20% | 路由计数 |
| 反馈量 | 内测期 ≥ 10 条/周 | `data/feedback.jsonl` |
| 质量 | API 5xx < 1%，P0 缺陷 0，首屏 LCP < 2.5s | 日志 + Lighthouse |
| 隐私 | 0 第三方广告/追踪 SDK | 代码审查 |

> 当前刻意不接第三方统计：孕期与敏感史属于敏感信息，产品早期用本机指标与人工访谈更稳妥。

## 四、路线图

### P0 · 本周必须收口

1. **AI 模型可用性**：当前视觉 Key 分组只有画图模型，研究 API 也还没有文本模型。视觉要换支持看图的 Key；研究要配一个能稳定输出 JSON 的文本模型。两者都可以在控制台配置，不配时拍照/自动研究不会假装成功。
2. **分享链路验收**：真实双设备打开、链接失效态、30 天清理、隐私提示。
3. **移动端走查**：390px 下首页、报告、成分库、历史、管理控制台五个页面。
4. **部署脚本**：一条命令起前后端；明确生产环境不要把 8082 直接暴露公网。

### P1 · 两周内

1. **双品对比**：同一档案对比两瓶，复用现有报告组件。
2. **报告 PDF / 图片导出**：比赛与社交传播需要可离线保存的资产。
3. **成分库扩到 150 条**，每条补来源字段（法规条款 / INCI / 品牌标签）。
4. **账号与云端历史（可选）**：只有在确认要做多设备时才上，不要为了「像产品」硬加登录。

### P2 · 省赛前

1. 数据运营后台：成分审核、反馈处理、分享统计。
2. 监测与告警：接口错误率、视觉模型失败率、分享 404 率。
3. 内容 A/B：结论卡文案、示例配方的转化。
4. 合规评审：隐私政策、数据保留、医疗边界。

### 明确不做

- 商品评分、带货推荐、替代品推荐。
- 医疗诊断、用药建议。
- 为了融资故事堆砌的「AI 聊天」入口。

## 五、风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| 成分库准确性 / 法规更新 | 结论错误，直接伤害信任 | 每条数据留来源；库版本号；每季度复核 |
| 视觉模型依赖 | 拍照入口不可用时像坏产品 | 管理控制台可换模型；失败可粘贴；未验证时明确提示 |
| AI 研究幻觉 | 编造法规限量或错误风险，影响结论 | 结果先进入「待研究」，报告注明 AI 补全并展示置信度与依据；人工确认后转为「已确认」，也可拒绝移出匹配 |
| 孕期 / 敏感数据隐私 | 用户不敢填，或分享泄露 | 默认本机；分享前明确提示；不接第三方追踪 |
| 单机存储上限 | 历史 / 分享多了会满 | 历史 20 条；分享 30 天清理；后续迁 DB |
| 分享链接滥用 | 任意人可写报告文件 | 不可猜测 ID；大小限制；后续加频控 |
| 分享可达性 | 在 `localhost` 上生成的链接，换设备打不开 | 弹层与 README 提示「跨设备用局域网 IP 再分享」；公网部署前不对外承诺分享 |
| 一个人维护 | 改动容易回归 | 规则引擎回归测试；版本与健康接口；README |

## 六、下一轮完成的定义（DoD）

- 新用户 30 秒内知道「贴什么、点哪里、得到什么」。
- 报告可以被命名、回看、分享，且分享页能独立解释自己。
- 任一失败态都有下一步动作，不出现上游 JSON。
- 规则改动有测试，版本号只有一个来源。
- 数据来源、隐私、边界在页面上可查。
- 手机与桌面各走一遍无阻断。
