## 1. 一页速览

| 项 | 内容 |
|---|---|
| 项目名 | 成分镜（Ingredient Lens） |
| 一句话 | 把化妆品包装背面那片没人看得完的小字，翻译成「对你」的结论 |
| 形态 | Web 应用（PC + 移动端响应式），Vue 3 + Vite 前端 / Spring Boot 2.7 后端 |
| 参赛 | 全国高校 AI Web 开发挑战赛 · 本科 B 组（非 985/211 普通本科）；省赛作品提交截止 2026-11-18 |
| 规模 | 前端 10,952 行（24 个 Vue 组件）、后端 5,443 行（33 个 Java 文件）、6 个测试类 48 个用例 |
| 状态 | v1.0 产品化原型，可完整离线演示；AI 能力已接入主力链路（视觉识别 + 成分研究） |

| 存储 | 本地 JSON 文件（无数据库），单机部署 |

**核心论点**：法规要求成分按含量从高到低排列（≤0.1% 者可任意排列）。这条规则公开、可验证，但几乎没人拿它做推理——**位次就是含量的代理变量，却被整个行业浪费了**。

## 2. 问题、用户、立场

### 2.1 要解决的问题

一瓶号称「烟酰胺美白」的精华，烟酰胺排在第 12 位。它前面还有 11 个成分，含量大概率不到 1%——这不是美白精华，这是**概念添加**。消费者没有能力做这个推理，而现有成分查询工具只回答"这个成分是什么"，不回答"它排在第几意味着什么"。

### 2.2 目标用户

1. 有明确诉求的普通消费者（敏感肌、孕期/备孕、油痘肌）——需要"这瓶适不适合我"，而不是成分百科；
2. 内容创作者（测评博主）——需要可引用的、带依据的结论；
3. 二次触达场景：门诊/皮肤管理前的自查、送礼前的判断。

### 2.3 明确不做（产品边界）

- 不评价商品优劣、不做商品评分、不带货推荐（避免利益冲突）
- 不做医疗诊断、不给用药建议
- 不做"通用 AI 聊天框"——AI 必须出现在不可替代的位置（感知与表达），判定交给规则
- 成分匹配**不走向量检索**：`羟苯甲酯` 与 `羟苯丙酯`、`1,2-丙二醇` 与 `1,2-戊二醇` 在向量空间里几乎重合，但风险等级不同，混淆就是安全事故

## 3. 功能清单

### 3.1 已实现

**输入**
- 成分表文本粘贴，兼容 `1,2-戊二醇` 这类数字逗号、全角/半角分隔符、`成分表：` 前缀
- 拍照识别（VLM）：一次返回成分表文本 + 产品名，前端在产品名为空时自动填入
- 实时切分预览：输入时显示"会切出几个成分"
- 格式自检：识别不出分隔符时提示，支持"按空格切分"一键修复（OCR 常见）
- 3 个内置示例配方（美白精华 / 抗老面霜 / 控油洁面），无需 AI Key 即可完整演示

**档案与判定**
- 个体化档案：肤质（干/油/混合/中性）、敏感肌开关、孕期状态；本地记忆，刷新不丢
- 配方梯队推断：前 5 / 6–10 / 11 位之后三档，标记"概念添加"
- 规则引擎：孕期禁忌、敏感肌致敏、致痘性（油皮/混油）、法规限量、强刺激提示
- 同类风险自动合并（"以下 5 个成分对敏感肌可能引起不适"），避免制造新噪音
- 可信度保护：全部未识别 → "未能解读"；识别覆盖率不足 → "信息不足"（不把"没认出来"误报成"可以放心"）

**报告**
- 结论卡（good / caution / avoid）、配方梯队可视化（未收录成分以虚线占位、排位不跳号）
- 风险分组、功效成分定位（第几位 → 概念添加/中等/主要功效）
- 法规提示、待补全占位（不展示未识别名单）
- 报告页内改档案：保留旧结论、后台重算，并说明"风险成分 6 → 2"
- 成分详情卡：点击梯队/功效/风险里的成分名弹出（深度描述、风险、排位、别名、备注），Esc/遮罩关闭
- 报告资产化：产品名、分析编号、生成时间、规则库版本；本机历史最近 20 份；`#/s/<id>` 短链分享（30 天自动清理）
- 一键复制报告（局域网 HTTP 下 Clipboard API 不可用时降级为"已全选"弹层）、打印样式

**内容与运营**
- 成分库页（90 条，搜索 / 角色 / 风险筛选）、解读方法页、关于与隐私页、404/分享失效页
- 用户反馈（本地 JSONL）
- PWA manifest、OG 分享图、`/api/version`、`/api/health`

**管理控制台**（`#/admin`，工程可见但对评委不可见）
- 概览 KPI、API 配置（总 API / 视觉 / 研究三级回退，保存即生效、模型列表拉取、视觉与研究连通性测试）
- 成分数据三态（待研究 / 已确认 / 已拒绝）、搜索筛选排序、增删改、批量审核、恢复内置库
- AI 研究（单条 / 批量最多 10 个 / 研究全部待研究），结果带置信度与依据，先回「待研究」并立即参与匹配，管理台可确认或拒绝
- 研究任务队列（自动补全未收录成分，失败可重试、可删除）
- 分享报告、用户反馈、系统状态（路径、版本、安全边界）
- 管理鉴权：内存令牌 12 小时，写接口要求 Bearer

### 3.2 未实现（已知）

- LLM 生成式解释：报告文案目前**全部是模板字符串**，模型不参与最终结论表达
- RAG：无向量库、无检索增强生成（成分匹配是精确名 → 别名 → 包含匹配 → 英文编辑距离兜底）
- Agent / Function Calling：只有后台研究任务队列，没有规划与工具调用
- MCP：未接入
- 语音输入/播报、视频、图像生成
- 双品对比、报告 PDF/长图导出、离线演示包
- 账号体系（刻意不做）、数据库（JSON 文件）

## 5. AI 技术方案

### 5.1 三个 AI 使用点

| 环节 | 模型 | 输入 | 输出 | 为什么必须用模型 |
|---|---|---|---|---|
| 拍照识别 | 视觉模型（Qwen-VL 系） | 包装照片 base64 | 成分表文本 + 产品名 | 传统 OCR 无法处理曲面、反光、中英混排 |
| 成分研究 | 文本模型（DeepSeek 系） | 成分名 + 上下文 | 结构化 JSON（15 字段） | 长尾成分无现成数据，需要世界知识 |
| 报告解释 | **未实现** | — | — | （方案书承诺"结论 → 人话"交给模型） |

调用方式：OpenAI 兼容 `/chat/completions`，Base URL / Key / Model 可在管理台热配置（三级回退：功能字段 → 总 API → 环境变量）。

### 5.2 视觉识别 Prompt（代码原文）

```
这是一张化妆品包装照片。请提取两件事，并严格输出一个 JSON 对象，不要 Markdown、不要解释：
{"productName":"包装上清晰可见的品牌+产品名；看不到就填空字符串；不要猜","ingredients":"成分表里的成分名称，按包装原始顺序，用中文顿号分隔；不翻译、不补全"}
productName 最多 40 字，只填能直接读到的名字；不要把成分表文字、广告语或使用方法当成产品名。如果图片里没有成分表，ingredients 填：未识别到成分表。
```

参数：`max_tokens=800`；图片以 `data:<mime>;base64,` 内联传参。
返回：`{ productName, ingredients }` 的 JSON（**不含坐标/位置信息**）。

### 5.3 成分研究 Prompt（全文）

System：
```
你是化妆品成分数据库研究员。你只输出一个 JSON 对象，不要 Markdown、不要解释、不要代码块。
不确定的法规限量必须留空，不要编造。
```

User：
```
请研究这个化妆品成分：{query}
它出现在这份成分表中（仅供上下文，不要研究其他成分）：{context}
只输出一个 JSON 对象，字段如下：
{
  "name": "标准中文名（最多40字）",
  "aliases": ["INCI名", "常见别名"],
  "role": "基质|功效|防腐|香精|防晒|表活",
  "cat": "分类，如保湿/美白/防腐/溶剂",
  "function": "一句话作用，最多200字",
  "description": "2–4句、80–220字的深度描述：它是什么、在配方里的实际作用、常见搭配/体系、适合或不适合谁、常见宣传误区或使用注意；不要广告腔，不要编造限量",
  "safety": "low|medium|high",
  "comedo": 0,
  "irrit": "low|medium|high",
  "preg": "safe|caution|avoid",
  "sensitive": "safe|caution|avoid",
  "limit": "法规限量；不确定必须留空",
  "note": "一句使用提示，最多200字",
  "confidence": 0.0,
  "evidence": "依据来源或推断理由，最多300字"
}
规则：不要编造法规限量；不确定的字段用空字符串或保守值；confidence 0–1；只输出 JSON。
```

参数：`temperature=0.1`、`max_tokens=900`、30 秒超时、3 线程池、失败缓存 10 分钟、批量单次上限 10。

### 5.4 可控性与安全设计（本项目的强项）

1. **可追溯闭环**：AI 研究结果先进入"待研究"状态，参与匹配但标注「AI 补全」；管理台可复核字段并转"已确认"，也可拒绝出库
2. **不编造限量**：prompt 明确要求不确定留空；限量字段为空则不展示法规提示
3. **置信度与依据**：每条 AI 结果带 `confidence` 与 `evidence`，管理台可见
4. **降级不假装**：未配置 Key → 明确提示"未配置视觉模型"，不伪造成功；识别失败 → 可重试/改用粘贴
5. **结论可信度保护**（前端）：未识别比例高时降级为"未能解读/信息不足"，绝不渲染成绿色"可以放心"
6. **不生成医疗结论**：全站禁用"会烂脸""有毒"类措辞，只陈述成分属性与法规限量
7. **数据不外发**：成分库、报告、反馈全在本机；无第三方统计/追踪 SDK
8. **管理面**：令牌仅内存、12h 过期、常数时间比较；数据目录不在仓库内

### 5.5 研究任务队列（当前唯一的"工作流"）

```
扫描发现未收录 token
   → enqueue（按名称去重，已存在则不重复建）
   → 状态 QUEUED
   → worker 每 5 秒认领 1 条 → RESEARCHING
   → 调模型（30s 超时）→ 成功：写库 → DONE
                        → 失败：保留 error + attempts → FAILED（可重试）
   → 服务重启时 RESEARCHING 重置为 QUEUED（避免永久卡住）
   → 特殊情况：括号变体（如「(日用)香精」→「香精」）自动并成别名，不报重名错误
```

它具备"异步、可观测、可重试、幂等"的工程特征，但**没有规划、没有工具调用、没有自主决策**——严格说是一个任务队列，不是 Agent。

## 6. 规则引擎（判定全部确定性）

流程：`切分 → 清洗 token → 匹配知识库 → 计算排位/tier → 逐条规则产出 flag → 同类合并 → 结论`

| 规则 | 触发条件 | 等级 |
|---|---|---|
| 孕期禁忌 | 档案孕期 && 成分 `preg=avoid` | high |
| 孕期谨慎 | 孕期 && `preg=caution` | medium |
| 敏感肌禁用 | 敏感 && `sensitive=avoid` | high |
| 敏感肌谨慎 | 敏感 && `sensitive=caution` | medium |
| 致痘 | `comedo>=3` && 肤质为油/混油 | medium |
| 法规限量 | 成分有 `limit` | info |
| 强刺激 | 非敏感 && `irrit=high` | medium |
| 概念添加 | 功效成分排位 ≥ 第 11 位 | 报告文案 |
| 香精提示 | 敏感 && 配方含香精 | 文案 |

结论阈值：任一 high → `avoid`；否则任一 medium → `caution`；否则 `good`。

梯队：index 0–4 → `core`；5–9 → `middle`；≥10 → `tail`。上限 150 个成分（超出标记 `truncated`）。

### 7.1 成分记录（JSON，内置 60 条 / 自定义覆盖）

| `f` | 一句话作用 | 抑制黑色素向角质层转运… |
| `ds` | AI 深度描述（2–4 句） | — |

| `pg` | 孕期 | safe/caution/avoid |

## 9. 前端实现

- **技术**：Vue 3（Composition API）+ Vite 5，**纯 JavaScript（无 TypeScript）**；无 UI 框架、无 CSS 框架，样式手写（设计变量集中在 `style.css`）
- **路由**：自写 hash 路由（`#/`、`#/ingredients`、`#/method`、`#/history`、`#/about`、`#/admin`、`#/s/<id>`），`App.vue` 1487 行承担路由与编排
